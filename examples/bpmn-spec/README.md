# BPMN 2.0 Specification & bpmn.js Showcase

Этот пример демонстрирует полную поддержку спецификации BPMN 2.0 в Go-клиенте NativeBPM и показывает, как интегрировать интерактивную визуализацию процессов с помощью библиотеки **bpmn.js** в реальном времени.

Все файлы схем, скрипты и веб-ресурсы встроены в бинарный файл с помощью Go-директивы `//go:embed`, что делает пример переносимым и запускаемым одной командой.

---

## Что демонстрирует пример?

В папке `bpmn/` находятся 4 схемы, покрывающие ключевые разделы спецификации BPMN 2.0:

1. **Шлюзы (Gateways):**
   - **Exclusive Gateway (`Gateway_Exclusive`):** ветвление процесса по условию `${score > 50}` (задается при старте).
   - **Parallel Gateway (`Gateway_Parallel`):** разделение потока на параллельные ветки (User Approval и фоновые проверки) с последующим объединением.
2. **События (Events):**
   - **Boundary Timer Event (`Event_Boundary_Timer`):** прерывание шага по таймеру (2 минуты) с эскалацией.
   - **Boundary Message Event (`Event_Boundary_Message`):** асинхронное прерывание шага при получении сообщения `cancelOrder`.
   - **Boundary Error Event (`Event_Boundary_Error`):** обработка бизнес-ошибки `PAYMENT_FAILED`, выбрасываемой Go-воркером.
3. **Подпроцессы (Subprocesses):**
   - **Embedded Subprocess (`SubProcess_Embedded`):** локальная область видимости с собственным жизненным циклом и граничным обработчиком ошибок `SHIPPING_FAILED`.
   - **Event Subprocess (`SubProcess_Event`):** глобальный обработчик событий внутри процесса, прерывающий исполнение при отправке сообщения `cancelFulfillment`.
4. **Интеграция с DMN (Decision Tables):**
   - **Business Rule Task (`Activity_DMN_Discount`):** вызов таблицы решений DMN 1.3 (`decision.dmn`) для расчета скидки на основе уровня лояльности клиента (`membership`), результат которого считывается последующим Go-воркером.

## Архитектура подсветки активных нод

Визуализация в реальном времени построена на взаимодействии фронтенда и Go-бэкенда:
1. Фронтенд инициализирует `BpmnJS` в режиме просмотра (Viewer).
2. При выборе процесса фронтенд запрашивает XML-схему с бэкенда (`GET /api/processes/{key}/xml`) и рендерит её.
3. После запуска инстанса фронтенд начинает опрашивать бэкенд каждые **1.5 секунды** по эндпоинту `GET /api/instances/{id}/active-activities`.
4. Бэкенд запрашивает дерево активностей из Camunda Engine API (`/process-instance/{id}/activity-instances`) и возвращает плоский список активных `Activity ID`.
5. Фронтенд накладывает CSS-класс на SVG-элементы диаграммы с помощью API `bpmn.js`:
   ```javascript
   const canvas = bpmnViewer.get('canvas');
   canvas.addMarker(activityId, 'highlight-active-node');
   ```
6. В CSS задан неоновый пульсирующий эффект для класса `.highlight-active-node`, что визуально выделяет текущие шаги процесса на схеме.

## Как запустить пример?

### 1. Поднимите Camunda Engine
Если инфраструктура еще не запущена, перейдите в папку `camunda/docker/` и выполните:
```bash
docker-compose up -d
```
Это запустит Camunda на порту `8080`.

### 2. Запустите Go-бэкенд примера
Из корневой директории репозитория выполните:
```bash
go run ./camunda/examples/bpmn-spec/main.go
```
*По умолчанию бэкенд запускается на порту `8081` и подключается к Camunda на `http://localhost:8080`. Вы можете переопределить это через переменные окружения `PORT` и `CAMUNDA_URL`.*

### 3. Откройте Веб-панель
Перейдите по адресу:
[http://localhost:8081](http://localhost:8081)

## Интерактивный сценарий для тестирования

1. **Gateways Process:**
   - Выберите схему в меню слева.
   - Нажмите **Start Process Instance**. Задайте `Score = 75` (или `30` для ветки Low Score).
   - Вы увидите, как процесс мгновенно пройдет инициализацию, выберет нужную ветку по значению Score и остановится на шаге **User Approval** (подсветится зеленым).
   - В правой панели появится форма User Task. Нажмите **Complete Task**, чтобы продвинуть процесс до конца.

2. **Events Process:**
   - Запустите инстанс. Шаг **Process Order** остановится на ручном подтверждении (User Task).
   - Вы можете нажать **Msg: cancelOrder** в правой панели, чтобы сымитировать отмену заказа. Вы увидите, как активный маркер мгновенно переместится на обработку отмены и процесс завершится.
   - Либо запустите новый инстанс и сразу нажмите **Complete Task** в форме. Процесс перейдет на шаг **Process Payment** (Service Task).
   - Если при старте вы выбрали галку **Simulate Payment Failure**, то Go-воркер выбросит BPMN Error `PAYMENT_FAILED`. Граничный Error Event поймает ошибку, перенаправит поток в обработчик ошибок, и процесс завершится по неуспешной ветке.

3. **Subprocesses Process:**
   - Запустите процесс. Вы увидите, как токен зайдет внутрь встроенного подпроцесса (Embedded Subprocess) и поочередно пройдет шаги упаковок и отправок.
   - Если при старте вы выбрали **Simulate Shipping Failure**, то на шаге отправки сработает граничное событие ошибки `SHIPPING_FAILED`, перенаправив процесс на возврат средств клиенту (`Refund Customer`).
   - Вы также можете нажать кнопку **Msg: cancelFulfillment** в любой момент, пока процесс находится внутри подпроцесса, чтобы сработал прерывающий Event Subprocess, сбросил текущее состояние и перевел процесс в ветку высвобождения стока (`Release Stock`).
